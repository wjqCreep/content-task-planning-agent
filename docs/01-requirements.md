# 01 需求

## 用户与目标
运营人员给出「主题、预算、截止时间」，Agent 在预算与时限内完成一份内容活动方案（素材 + 脚本），并保存。

## 输入与材料
- 输入：主题、预算（模拟单位）、截止时间（小时）。
- 合成数据：`data/materials.json`（8 条素材，含 1 条授权过期）、`data/tool_costs.json`（工具费用与耗时）。
- 工具：素材检索 `search_materials`、脚本生成 `generate_script`（premium / standard / lite 三档）、成本估算 `estimate_cost`、方案保存 `save_plan`。均为本地函数，不访问外部服务。

## 交付结果
任务计划与各步骤状态、工具结果、费用与耗时合计、已保存方案路径；未完成时给出原因与缺口（还差多少预算/小时）。

## 范围
包含：ReAct 决策循环、预算/时限/依赖守卫、步数与工具调用上限、状态持久化、幂等与失败续跑、故障注入。
不包含：界面、线上部署、多 Agent、生产级 Runtime、真实素材库与真实计费。

## 成功标准（验收点 → 对应用例，详见 03-evaluation.md）
| 验收点 | 标准 |
|---|---|
| 正常完成 | 三步全部 success，已保存，费用 ≤ 预算 |
| 缺预算或截止时间 | 返回 needs_input，不调用任何工具、无费用、无文件 |
| 工具失败 | 失败步骤不记为成功；模型调整（重试/降档/停止）；已成功步骤结果保留且不重复计费 |
| 预算超限 | 参考实例：预算 10，premium 估 12 → 模型改选 standard（8）再估算、保存 |
| 无可行方案 | 返回 incomplete + 缺口，不保存、不扣费 |
| 重复执行 | 同输入已完成则不重复执行、不重复计费、不重复写文件 |
| 步数/调用上限 | 达到上限返回明确的 incomplete 状态 |
| 加分：失败步骤续跑 | 同输入再跑，只执行失败步骤 |
